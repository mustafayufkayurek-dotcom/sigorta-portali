Sunucu Satın Alma (Hetzner Örneği)

Aşağıdaki adımlar Hetzner için gösterilmektedir. Diğer sağlayıcılar için arayüz farklı olsa da mantık aynıdır.

  1. 1
    Hesap Açın Tarayıcınızda https://hetzner.com adresini açın. Sağ üstteki "Sign Up" butonuna tıklayın. E-posta adresinizi ve şifrenizi girin.
  2. 2
    Ödeme Yöntemini Ekleyin Hesabınıza giriş yaptıktan sonra sol menüden "Billing" → "Payment" seçin. Kredi kartınızı veya PayPal hesabınızı ekleyin.
  3. 3
    Yeni Sunucu Oluşturun Sol menüden "Servers" → sağ üstteki "+ Create Server" butonuna tıklayın.
  4. 4
    Konum Seçin "Location" bölümünden "Falkenstein" (Almanya) veya "Helsinki" (Finlandiya) seçin. Türkiye'ye en yakın veri merkezi Falkenstein'dır.
  5. 5
    İşletim Sistemi Seçin "Image" bölümünden "Ubuntu 22.04" seçin.
  6. 6
    Sunucu Tipi Seçin "Type" bölümünden "Shared vCPU" → "CX22" seçin (2 vCPU, 4 GB RAM, ~5€/ay).
  7. 7
    Root Şifresi Ayarlayın "Authentication" bölümünden "Password" seçin ve güçlü bir şifre girin. Bu şifreyi mutlaka bir yere not edin — sunucunuza girerken kullanacaksınız.
  8. 8
    Sunucuyu Satın Alın Sayfanın altındaki "Create & Buy now" butonuna tıklayın. Birkaç saniye içinde sunucunuz hazır olacak.
  9. 9
    IP Adresini Not Alın Sunucu listesinde oluşturulan sunucunuzu göreceksiniz. IPv4 adresini not alın (örn: 65.21.123.45). Bu adres sunucunuzun internet adresidir.

Sunucuya Bağlanma (SSH)

SSH, bilgisayarınızdan uzaktaki sunucuya güvenli şekilde bağlanmanızı sağlayan bir yöntemdir. Sanki sunucunun klavyesinin başında oturuyormuşsunuz gibi komut çalıştırabilirsiniz.

macOS'te Terminal'i Açma

  1. 1
    Spotlight'ı Açın Klavyede Command (⌘) + Boşluk tuşlarına birlikte basın.
  2. 2
    Terminal Arayın Açılan arama kutusuna "Terminal" yazın ve Enter'a basın. Siyah bir pencere açılacak.
  3. 3
    Sunucuya Bağlanın Aşağıdaki komutu yazın ve Enter'a basın (65.21.123.45 yerine kendi sunucu IP'nizi yazın):
    $ ssh root@65.21.123.45
  4. 4
    "yes" Yazın İlk bağlantıda şöyle bir soru çıkacak: "Are you sure you want to continue connecting (yes/no)?"
    yes yazın ve Enter'a basın.
  5. 5
    Şifrenizi Girin Sunucu satın alırken belirlediğiniz şifreyi yazın. Yazdığınız karakterler görünmez — bu normaldir, güvenlik için gizlenir. Yazıp Enter'a basın.
✓
Bağlantı Başarılı! Ekranda root@sunucu-adi:~# şeklinde bir yazı görüyorsanız sunucuya bağlandınız. Artık sunucuda komut çalıştırabilirsiniz.
⚠
Bağlantıyı Kesmeden Önce Sunucudan çıkmak için exit yazıp Enter'a basın. Terminal penceresini direkt kapatmayın — çalışan işlemleri yarıda kesebilir.
5
Docker Kurulumu

Docker, uygulamaları "konteyner" adı verilen izole kutucuklar içinde çalıştıran bir yazılımdır. Projenin tüm bileşenleri (veritabanı, backend, frontend) Docker ile başlatılmaktadır.

Sunucuya bağlıyken aşağıdaki komutları sırayla çalıştırın:

1. Sistemi Güncelle

# Mevcut yazılımları güncelle (~2-3 dakika sürer) $ apt-get update && apt-get upgrade -y

2. Docker'ı Kur

# Docker'ı tek komutla kur $ curl -fsSL https://get.docker.com | sh

3. Docker'ı Otomatik Başlatmaya Al

# Sunucu yeniden başladığında Docker otomatik açılsın $ systemctl enable docker $ systemctl start docker

4. Kurulumu Doğrula

$ docker --version # Çıktı şöyle görünmeli: Docker version 25.x.x, build xxxxxxx
✓
Docker hazır! "Docker version" çıktısını gördüyseniz kurulum tamamdır.

Projeyi Sunucuya Yükleme

Projeyi sunucuya yüklemek için Git kullanılır. Git, yazılımları versiyon kontrolüyle indirip güncellemenizi sağlar.

1. Git'i Kur

$ apt-get install -y git

2. Kurulum Klasörünü Oluştur

# /opt/sigorta klasörüne kuracağız $ mkdir -p /opt/sigorta $ cd /opt/sigorta

3. Projeyi İndir

# GitHub adresinizi yazın $ git clone https://github.com/KULLANICI_ADI/sigorta-hasar-sistemi.git . # İndirme tamamlandıktan sonra dosyaları listele $ ls
ℹ
GitHub Adresi Nerede? Projenizin GitHub adresini projeyi geliştiren ekipten alın. Format şöyle olmalı: https://github.com/kullanici/proje-adi

Güncellemeleri Almak İçin

Yazılım güncellemesi yapıldıktan sonra sunucuya çekmek için:

$ cd /opt/sigorta $ git pull origin main $ bash scripts/deploy.sh

Ortam Değişkenlerini Ayarlama

Ortam değişkenleri, uygulamanın hangi veritabanına bağlanacağını, hangi şifreleri kullanacağını gibi önemli ayarları içeren bir yapılandırma dosyasıdır.

1. Şablon Dosyasını Kopyala

$ cd /opt/sigorta $ cp .env.production.example .env.production

2. Dosyayı Düzenle

# nano metin editörünü aç $ nano .env.production
ℹ
nano Editörü Kullanımı
  • Ok tuşlarıyla hareket edin
  • Değiştirmek istediğiniz yere gelin ve yazın
  • Bitince Ctrl + X basın → Y basın → Enter basın

3. Güçlü Şifreler Üretin

Her şifre için aşağıdaki komutu çalıştırın, çıkan metni kopyalayıp .env dosyasına yapıştırın:

# PostgreSQL şifresi için: $ openssl rand -base64 24 # Redis şifresi için: $ openssl rand -base64 24 # JWT_SECRET için (daha uzun olmalı): $ openssl rand -hex 32 # MinIO şifresi için: $ openssl rand -base64 16

8
Sistemi Başlatma (Deploy)

Tüm ayarlar yapıldıktan sonra tek bir komutla sistemi başlatabilirsiniz:

$ cd /opt/sigorta $ bash scripts/deploy.sh

Bu komut şunları otomatik olarak yapar:

  • Ayarları kontrol eder
  • Docker image'larını oluşturur (5-10 dakika sürer)
  • Veritabanını başlatır
  • Backend ve frontend'i başlatır
  • Veritabanı tablolarını oluşturur
  • Nginx proxy'yi başlatır
ℹ
İlk kurulum 10-15 dakika sürebilir — Docker her şeyi internetten indiriyor. Sonraki başlatmalar çok daha hızlı olur.

Çalışan Servisleri Görme

$ docker compose -f docker-compose.prod.yml ps

Tüm servislerin "running" veya "healthy" durumunda olması gerekir.

Logları Takip Etme

# Tüm servislerin logları (Ctrl+C ile çıkılır) $ docker compose -f docker-compose.prod.yml logs -f # Sadece backend logları $ docker compose -f docker-compose.prod.yml logs -f backend # Sadece nginx logları $ docker compose -f docker-compose.prod.yml logs -f nginx

  1. 1

    AlanYazacağınız Değer

Sunucu terminalinde aşağıdaki komutu çalıştırın (alanadi.com.tr yerine kendinizinkini yazın):

Ya da tarayıcıdan kontrol etmek için: dnschecker.org adresine gidin, alan adınızı yazın ve tüm lokasyonlarda sunucu IP'nizi görüp görmediğinizi kontrol edin.

SSL Sertifikası (HTTPS)

SSL sertifikası, sitenizin https:// ile erişilmesini ve tüm iletişimin şifrelenmesini sağlar. Let's Encrypt ücretsiz SSL sertifikası vermektedir.

⚠
Önce DNS Yayılmasını Bekleyin! SSL sertifikası almadan önce alan adınızın sunucu IP'nize yönlendirilmiş olması gerekir. Bölüm 9'u tamamlayıp DNS'in yayıldığından emin olun.

Deploy script'i SSL sertifikasını otomatik alır. Eğer deploy sırasında DNS henüz yayılmamışsa, DNS yayıldıktan sonra şu komutu çalıştırın:

$ cd /opt/sigorta # SSL sertifikasını al (e-posta adresinizi girin) $ docker compose -f docker-compose.prod.yml exec certbot \ certbot certonly \ --webroot \ --webroot-path /var/www/certbot \ --email noreply@sirketim.com.tr \ --agree-tos \ --no-eff-email \ -d alanadi.com.tr \ -d www.alanadi.com.tr # Nginx'i yenile (SSL'i devreye almak için) $ docker compose -f docker-compose.prod.yml exec nginx nginx -s reload

SSL Yenileme Otomatik mi?

Evet. Certbot container'ı her 12 saatte bir sertifikayı kontrol eder ve süresi dolmadan önce (30 gün öncesinde) otomatik olarak yeniler. Elle bir şey yapmanıza gerek yok.

✓
Başarılı! Tarayıcınızdan https://alanadi.com.tr adresini açtığınızda adres çubuğunda kilit simgesi görüyorsanız SSL çalışıyor demektir.

İlk Admin Kullanıcısı ve Başlangıç Verisi

Sistem kurulduğunda veritabanı boş gelir. Seed (başlangıç verisi) komutu ilk admin kullanıcısını ve temel verileri oluşturur.

⚠
Seed bir kez çalıştırılmalı! Bu komut yalnızca ilk kurulumda çalıştırılır. Tekrar çalıştırırsanız veriler mükerrer oluşabilir.

Seed Komutunu Çalıştırma

$ docker exec -it sigorta-backend sh -c "cd /app/apps/backend && npx prisma db seed"

Komut tamamlandıktan sonra varsayılan admin bilgilerini geliştirici ekibinden alın. Sisteme ilk giriş yaptıktan sonra şifrenizi mutlaka değiştirin.

Admin Şifresini Değiştirme

  1. Siteye giriş yapın.
  2. Sağ üstteki kullanıcı ikonuna tıklayın.
  3. "Profil" veya "Hesap Ayarları" seçeneğini açın.
  4. Şifrenizi güncelleyin.
13
Otomatik Yedekleme Kurulumu

Yedekleme script'i her gece saat 02:00'de otomatik çalışacak şekilde ayarlanır. Her yedek sıkıştırılmış şekilde sunucuya kaydedilir ve 30 günden eskileri otomatik silinir.

Cron Görevi Oluşturma

# Cron editörünü aç $ crontab -e # İlk açılışta editör sorabilir, nano için 1 yazıp Enter'a basın # Açılan dosyanın EN ALTINA şu satırı ekleyin: 0 2 * * * /opt/sigorta/scripts/backup.sh >> /var/log/sigorta-backup.log 2>&1 # Kaydet: Ctrl+X → Y → Enter

Elle Yedek Alma

$ bash /opt/sigorta/scripts/backup.sh

Yedekleri Görmek

$ ls -lh /var/backups/sigorta/

Yedeği Geri Yükleme

Bir felakette veritabanını geri yüklemek için:

# backup_2026-01-15_02-00-00.sql.gz dosyasını geri yükle $ gunzip -c /var/backups/sigorta/backup_TARIH.sql.gz | \ docker exec -i sigorta-postgres \ psql -U sigorta_user -d sigorta_hasar

Sorun Giderme
SorunÇözüm
Site açılmıyor 1. docker compose -f docker-compose.prod.yml ps ile container'ların çalışıp çalışmadığını kontrol edin.
2. docker compose -f docker-compose.prod.yml logs nginx ile nginx loglarına bakın.
3. DNS yayıldı mı kontrol edin: nslookup alanadi.com.tr
SSL sertifikası hatası 1. DNS yayılmasını bekleyin (en az 30 dakika).
2. Deploy script'ini tekrar çalıştırın: bash scripts/deploy.sh
Backend başlamıyor docker logs sigorta-backend ile hata mesajını okuyun.
Genellikle .env.production'da eksik veya yanlış değer vardır.
Disk doldu df -h ile disk kullanımını görün.
docker system prune -f ile eski Docker katmanlarını temizleyin.
Güncelleme sonrası site çalışmıyor docker compose -f docker-compose.prod.yml restart ile tüm servisleri yeniden başlatın.
Tüm servisleri durdurmak docker compose -f docker-compose.prod.yml down
Tüm servisleri yeniden başlatmak docker compose -f docker-compose.prod.yml up -d

Destek

Çözemediğiniz bir sorunla karşılaşırsanız, aşağıdaki logları geliştirici ekibine iletin:
